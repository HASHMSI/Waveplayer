# Contributing

Start with [development](docs/development.md) and [testing](docs/testing.md). Keep changes focused; describe behavior, verification and limitations. Audio changes require both executable check programs. Resource/installer changes also require the [release checks](docs/releasing.md).

Preserve user-data paths, public filenames, resource identities and the Classic DLL unless a separate migration is reviewed. Do not commit personal music, settings, generated output or credentials. Use authorized recordings for optional listening checks.

Use the bug template for ordinary issues and read [SECURITY.md](SECURITY.md) before sharing sensitive information. Preserve the project [copyright notice](COPYRIGHT.txt) and the applicable [third-party credits](THIRD_PARTY_NOTICES.md).
